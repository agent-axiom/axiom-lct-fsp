# Анонимный доступ — v0.6.1

Причина прежнего 307: главная страница приложения безусловно вызывала requireChatGPTUser('/'). Public в настройках Sites само по себе не отменяет этот код. Документация платформы разрешает анонимные запросы к публичному Site без authenticated-user headers.

Исправление: optional getChatGPTUser на главной. Без входа используется /api/guest/* и отдельная таблица guest_workspaces; при входе прежние /api/* и персональные workspace остаются защищёнными. /api/account/* не принимают гостевой cookie как platform principal. Никакие fake headers, bypass tokens, внешние провайдеры, операторские ключи или постоянные credential grants не используются.

Сессия: 32 криптографически случайных байта, двухчасовой фиксированный срок, host-only cookie __Host-fsp_guest с HttpOnly/Secure/SameSite=Strict. В D1 только SHA-256 токена; URL/query и JSON не принимают токен или owner. Actor-cookie отдельный от персонального fsp_actor. Контакты открываются только пригласившему после принятия, в пределах собственной синтетической сессии. Отзыв согласия снимает видимость и контакт.

Ограничения: 128 активных сессий; 32 новых за скользящую минуту; 120 запросов на сессию за минуту; 256 KiB состояния; 16000 UTF-8 байт тела POST. Origin обязателен и должен совпадать, JSON обязателен, cross-site запросы отклоняются. Лимиты проверяются сервером, конкурирующие изменения защищены CAS. Просроченные записи удаляются лениво при следующем гостевом запросе. Сброс требует confirm=true и явного подтверждения в UI. Реальная почта не отправляется; регистрация допускает только @example.test.

Проверено до публикации: HTTP handlers с настоящими Request/Response и SQLite, отдельные cookie jars; анонимный state 200; регистрация/демо-код/тест/публикация/подбор/приглашение/принятие, отказ, отзыв контакта; повтор, refresh, cross-session invitation, посторонний работодатель, сброс, expiry, malformed/oversize requests, origin, cookie forgery, rate/capacity limits, concurrent writes, state-size cap. Личные операции без platform identity возвращают прежний 401; неправильная роль — 403. Public /api/account/state при выключенных реальных аккаунтах возвращает только безличный статус, как и раньше.

Это не браузерный e2e и не подтверждение реальной почты. Сетевой локальный runtime и браузер ранее ограничены средой. Настоящий анонимный HEAD/GET главной и гостевого API необходимо подтвердить после публикации, без cookie/служебных ключей/platform headers. Не заявлять 200 production до этого результата. Новая экспериментальная ротация 48 задач в этот выпуск не входит: банк остаётся v4 исходной v0.6.
