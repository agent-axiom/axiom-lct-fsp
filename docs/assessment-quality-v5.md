# Банк v5: содержательное снижение точного воспроизведения ответов

10 октября 2026. Локальная реализация без публикации и без изменения доступов.

## Изменение

Сохранены 2 специализации × 3 грейда, 12 заданий, 30 минут и порог 9/12 с минимумом 2/3 в каждом навыке. В каждом навыке теперь обязательны одна свежая задача с набором данных, одна из двух прежних прикладных задач и один из четырёх вопросов на знания. Банк вырос со 144 до 168 семейств. Четыре новых задания нельзя все пропустить и получить зачёт: остаётся максимум 8/12. Это не означает, что каждое из четырёх обязательно решить.

24 новых семейства включают Python-генераторы/try-finally, SQL NULL/group/window, HTTP байты/rate limit/If-Match, поиск/BFS/LRU, TypeScript-операции, React очереди обновлений/устаревшие ответы, CSS размеры/каскад, HTML фокусируемость/Tab/focus trap. Данные меняют результат или ветвление. Это короткие учебные упражнения, а не свидетельство квалификации Junior/Middle/Senior.

Версия повышена до 5. Старые реальные подтверждения и незавершённые тесты v4 требуют повторного тестирования через существующий механизм устаревания; история, выбранный грейд и ограничения смены сохраняются. Синтетические демонстрационные профили остаются явно синтетическими.

## Метод и границы независимости

До генератора зафиксированы `tests/fixtures/assessment-v5/protocol.json`: train seeds 671000..671499, кривые 1/5/20/100/500 обучающих попыток, evaluation seeds 972000..972299 для каждой категории, неизменные пороги и восемь профилей.

Отдельный AI-исполнитель написал эталон из контракта задач до чтения генератора. Он получает публичный текст/данные, навык и заданный уровень, не читает сохранённый ответ. Старые ответы вычисляются прежним семантическим oracle на полных v4-вариантах и переносятся по точному публичному тексту. Пропуск/конфликт эталона останавливает проверку. Это независимость реализации в рамках авторских заданий, не независимая экспертная или психометрическая валидация.

Модель утечки запоминает `text + format + sorted choices` с эталонными ответами на обучении. Во время проверки использует исключительно публичный DTO и отвечает «не знаю» на неизвестный ключ. Она не обобщает формулы, не нормализует числовые шаблоны и не решает неизвестные задания. Устойчивость к LLM, помощникам, анализу открытого исходника и формулам не измерялась.

Первый прогон сохранён как `iteration-1-results.json`: Frontend Junior ещё имел 19,33% зачётов по словарю. Второй содержательный шаг добавил к восьми кнопкам состояния hidden и inert-предка; это условия фокусируемости, а не случайная соль. Из SQL Senior удалено неиспользуемое поле limit. Итог измерен на тех же seeds: это адаптивная разработка, а не новый скрытый holdout. Старые цифры не скрываются.

## Интерпретация test-retest

Профили фиксируют способность решать семейства независимо от параметров. Показаны минимум/максимум/средний балл, доля зачётов и доля всех пар вариантов с разным pass/fail: `2*p*(N-p)/(N*(N-1))`. Это не измеренная надёжность повторного теста у людей. Профили all и none служат контролями; missing-first-skill не проходит даже с 75 баллами; all-applied получает 67 и не проходит.

Частичные профили остаются нестабильными. Изменение выборки и числа понятий не калибрует сложность. Улучшение сопоставимости или объективного определения профессионального грейда не заявляется. Малые пространства ответов у некоторых задач также позволяют более сильные угадывающие стратегии, которых этот exact-text benchmark не моделирует.

- `npm test`
- `npm run evaluate:assessment-quality`
- `npm run typecheck`
- `npm run lint`

Полные данные, SHA-256 генератора/эталона/протокола, кривые утечки, все профили, повторение текстов и разнообразие ответов: `tests/fixtures/assessment-v5/evaluation-results.json`. Исторические отчёты v3/v4 не переписаны.

Проверено локально: все 21 600 ответов шести категорий на 300 вариантах совпали с эталоном, неправильные ответы отклонены; 35 новых тестов прошли. Полный regression после cooldown fix: 363 теста, 363 прошли, 0 ошибок/пропусков. Typecheck, ESLint и production build прошли. React SSR и гостевой HTTP-сценарий входят в полный regression. Дополнительно создан PDF профиля с результатом банка v5 12/12; текст извлечён, обе страницы визуально просмотрены, переносы корректны. Браузерный E2E на опубликованном стенде не выполнялся; деплоя нет.

Профиль «все прикладные + знание-0/1» Frontend Junior ухудшился по доле пар с разным результатом: 10,13% → 15,88%. Не следует представлять этот patch как исправление test-retest.

## Дополнительный adversarial diagnostic: частый ответ по шаблону

Независимый рецензент добавил более сильную дешёвую стратегию: точное совпадение использует словарь; для нового текста берётся самый частый обучающий ответ для префикса до строки `Данные:`. Ничьи разрешаются первым встретившимся ответом. Обучение: те же 500 вариантов, оценка: те же 300. Новое правило не выбирается на основе тестовых ответов, но эта проверка добавлена после основного эксперимента и не была preregistered.

Обучающие метки этой диагностической стратегии берутся из сохранённых ключей генератора, а не независимого oracle. На inference используются только публичные DTO. Это модель утечки размеченного банка, не утечка поля answer через API.

## Исправление cooldown, обнаруженное независимым ревью

Устаревание evidence сбрасывает categoryConfirmed, поэтому прежняя логика не запускала 90 дней после успешной смены сохранённого исторического грейда. Теперь факт прежнего подтверждения определяется также успешной неотменённой исторической попыткой сохранённого грейда, исключая только что добавленную попытку. Не требуется новая колонка: история уже сохраняется в обоих хранилищах. Это отделяет актуальность доказательства от исторического факта; устаревшее подтверждение не становится актуальным автоматически.

Шесть дополнительных регрессий: same-grade, failed change и successful change на JSON-roundtrip и normalized SQLite после сохранения устаревшего профиля/reload. Проверяется сохранность истории, неизменность таймера при повторе/провале, новый таймер после смены, запрет немедленной следующей смены и разрешение ровно через 90 дней.

Независимое ревью исправления cooldown: 19/19 focused tests (6 migration + 13 quality policy); блокирующий дефект закрыт. Комбинированный regression после интеграции с параллельным matching patch требуется отдельно.
