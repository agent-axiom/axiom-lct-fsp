# Архитектура

React/Vinext → HTTP API → доменная логика → D1/SQLite. Приложение объединяет два кабинета и путь «кандидат → подбор → предложение → согласие → контакт».

## Основные модули

- `app/workspace.tsx`: интерфейс кандидата и работодателя, формы, поиск, приглашения.
- `lib/domain.mjs`: роли, команды, приватные DTO, история и переходы состояния.
- `lib/assessment.mjs`: банк заданий v4, проверка ответов и отдельные результаты навыков.
- `lib/matching.mjs`: распознавание ограниченного набора требований и объяснимый рейтинг.
- `lib/achievements.mjs`: проверка синтетического происхождения и бонус DEMO-достижений.
- `lib/storage.ts`: подготовленные SQL, optimistic concurrency по revision и повтор конфликтующих записей.
- `lib/guest-demo.mjs`: изолированные двухчасовые гостевые пространства и ограничения запросов.
- `lib/real-accounts.mjs`, `accounts-repository.mjs`, `email-outbox.mjs`: подготовленные ролевые аккаунты, нормализованные таблицы и email outbox. Реальный режим по умолчанию выключен.
- `lib/assessment-drafts.mjs`: черновик ответов в пределах вкладки, связанный с проверенной сервером личностью и попыткой.

Демонстрационный workspace хранится JSON-агрегатом. Подготовленный реальный режим использует отдельные нормализованные таблицы; данные двух режимов не смешиваются. Старый `account-service.mjs` остаётся reference-моделью для тестов и не обслуживает новый API.

## Доступ и приватность

Гостевой cookie не открывает личные пространства или реальные аккаунты. Контакт кандидата выдаётся только отправителю принятого приглашения при действующем согласии; отзыв согласия закрывает контакт и видимость в поиске. Роль реального аккаунта привязана к доверенному platform subject.

Черновики теста не отправляются на сервер и не содержат ключей проверки. `draftIdentity` служит псевдонимным разделителем кэша и не принимается для авторизации. Детали: [assessment-draft-ux-fix.md](assessment-draft-ux-fix.md).

## Подбор

Рейтинг: 80% соответствия распознанным требованиям и 20% теста. Внутри соответствия активные критерии нормируются: специализация 25, грейд 20, стек 45, самоописанный опыт 10. Без требований используется результат теста.

Явные фильтры специализации, грейда, стека и ФСП ограничивают выборку до ранжирования. Требования свободного текста могут оставаться мягкими; неизвестные условия требуют ручной проверки. Это ограниченный словарный алгоритм.

DEMO-достижение добавляет не больше 5 баллов в точной категории и только при отсутствии недостающих распознанных требований. Linked-флаг без доверенной синтетической записи бонуса не даёт. Подробности: [achievement-policy.md](achievement-policy.md), [matching-quality.md](matching-quality.md).
