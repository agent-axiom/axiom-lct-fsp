# v0.5: доказательства навыков и тестовый путь двух ролей

## Карточка работодателя

Раскрытие «Доказательства навыков» показывает дату завершения UTC, версию банка, категорию, общий результат и отдельные блоки навыков. Нужные по запросу навыки помечены «В запросе». Недостающие требования остаются в прежнем отдельном сообщении карточки; объяснения matching не дублируются.

Внутри каждого навыка можно раскрыть отдельные задания: номер в завершённой попытке, тип, результат «верно/неверно» и балл 0/1 либо 1/1. Это безопасная квитанция результатов, без формулировок, вариантов, ответов и идентификаторов концепций. Для старых попыток без сохранённых исходов строки отсутствуют.

Карточка использует только одну завершённую, успешно пройденную, принадлежащую кандидату попытку текущего банка. Дата, версия и баллы не смешиваются между попытками. Новый провал не заменяет успешное подтверждение; новый успех с меньшим баллом заменяет предыдущий. Проверяются ожидаемые четыре уникальных навыка, количества, проценты, итоговый балл и соответствие стеку профиля. Несогласованные записи не выдаются как текущие доказательства и не участвуют в подборе.

Каждая новая завершённая попытка сохраняет на сервере только дополнительный признак правильности задания рядом с существующим заданием. Ответ, введённый пользователем, дополнительно не сохраняется. Это позволяет показать агрегаты «прикладные / знания». Для старых завершённых попыток, где этот признак отсутствует, разбивка остаётся недоступной: она не восстанавливается догадкой. Схема SQL не меняется, используется существующее questions_json.

Публичный DTO собирается явным списком полей. В нём нет формулировок заданий, ключей/альтернатив ответов, concept ID, сырых ответов, активных тестов, чужих или неудачных попыток, email/контактов, issuer/subject и почтовых токенов. Открытие карточки ничего не изменяет и не даёт права отправлять ответы от имени кандидата.

Исходные fixtures помечены как синтетика: нет выдуманных даты, версии пройденного банка и числа верных заданий. Стаж/самоописание не считаются измеренными тестом. Результаты учебного банка не доказывают профессиональную пригодность; экспертная и психометрическая валидация не заявляются.

## Путь двух ролей в интерфейсе

1. Кандидат открывает профиль и тест, сохраняет согласие/публикацию.
2. Работодатель задаёт потребность, раскрывает доказательства и проверяет недостающие требования.
3. Работодатель отправляет предложение с зарплатой. Контакт по-прежнему закрыт.
4. Кандидат принимает или отклоняет приглашение. Принятие открывает контакт только отправителю при действующем согласии; отзыв согласия закрывает его снова.

Кнопки сохраняют выбранную тестовую роль, включая созданные во время демонстрации профили. В приглашении выбранный кандидат становится целью возврата. Это синтетические роли в одном workspace. Данный интерфейс не доказывает изоляцию двух настоящих браузерных сессий.

## Отдельная HTTP/SQLite проверка

`node scripts/verify-two-role.mjs --write` воспроизводит сценарий кандидата и работодателя с дополнительным посторонним работодателем. Полный отчёт: `two-role-verification.json`.

Проверяются trusted principal вместо подмены cookie/body/header, запрет неправильных ролей, отсутствие результатов без согласия, сохранение доказательств, скрытие контакта до принятия, отказ без раскрытия, доступ только отправителю и отзыв согласия. Все HTTP-ответы проверяются на no-store.

Подтверждение email задаётся непосредственно в изолированном SQLite fixture. Внешний fetch в сценарии запрещён и подсчитывается; выполнено 0 внешних отправок. Это backend/HTTP-интеграционный тест, не настоящее письмо, не проверка провайдера и не live/browser e2e. Runtime реального сайта остаётся выключенным по умолчанию.

## Совместимость и ограничения проверки

- Версия учебного банка остаётся 3. Новый выпуск интерфейса сам по себе не аннулирует результаты v0.4.
- История и правила устаревания/90-дневной смены грейда сохранены.
- Дополнительные поля доказательств описаны закрытыми схемами OpenAPI; UI рендерит measured/synthetic состояния настоящим React SSR.
- SSR, unit и HTTP-тесты не подменяют браузерную, мобильную и клавиатурную проверку. Если она не выполнена, это явно сообщается при передаче.
- PDF собственного профиля показывает те же дату/версию банка и доступную разбивку. Контакт в собственном PDF является существующим поведением и не выдаётся работодателю через карточку.
